# 2-1. 로그인 모듈 추가 — 작업 내역

## 브랜치

- `login_module` 브랜치 생성 후 작업.

## 추가·변경 파일

### `login_module.py` (신규)

- `reference/lomin_client.py`의 로그인 경로·헤더 패턴만 동기 `requests`로 이식.
- `POST {base}/cognition-api/api/v2/account/login`, JSON `{"email","password"}`.
- 응답에서 `response.type` + `response.token`으로 `Authorization` 값 조합 (`reference`와 동일).
- `base_url_from_workflow_url()`: `--workflow-url`의 origin으로 로그인 호스트 유도.
- `CachedLominAuth`: 토큰 문자열 캐시, 401 시 `invalidate()` 후 재로그인 가능.

### `request_api.py` (수정)

- 선택 인증: `--auth-email` / `--auth-password`, 또는 환경 변수 `LOMIN_AUTH_EMAIL` / `LOMIN_AUTH_PASSWORD`.
- 둘 중 하나만 주면 종료 메시지로 오류 처리.
- `--auth-base-url`: 로그인 전용 베이스 URL (미지정 시 워크플로 URL과 동일 호스트).
- 인증이 **없을 때**: 기존과 동일 — `params` JSON + 별도 `api_option` 폼 필드, `Authorization` 없음.
- 인증이 **있을 때**: `reference` 클라이언트와 같이 `params` 하나에 `api_key` + `api_option`을 JSON으로 넣어 전송; 요청마다 캐시된 `Authorization` 부착, HTTP 401이면 캐시 무효화 후 1회 재시도.

## 검토 문서 반영

- `cursor_result/2. 로그인 모듈 추가 검토.md` 권장: 선택적 경로, 베이스 URL 정리, 토큰 캐시·401 재시도, `requests` 동기, 참고 파일 그대로 복사 금지 → 위와 같이 반영.
